# DATA_MODEL.md

Сейчас публичный сайт контент не хранит динамически — новости лежат статически в `src/project.js` (поле `news`), правятся прямо в файле. Модель ниже описывает `store.js`/Supabase-хранилище на будущее, когда понадобится редактировать контент без деплоя.

Проект стартует в локальном режиме. Записи живут в браузере текущего устройства.

## Универсальная запись

- `id` — уникальный идентификатор.
- `record_type` — тип: заявка, результат квиза, клиент или задача.
- `payload` — полезные поля конкретной записи.
- `status` — текущий этап.
- `created_at` — дата создания.
- `updated_at` — дата изменения.
- `archived_at` — дата архивации.

## Владелец данных

До подключения базы локальные записи видит только этот браузер.

После подключения Supabase записи принадлежат `workspace_id`. Читать и менять их может участник рабочей области. Публичная форма может только создать ограниченный тип записи.

## Не храним

- платёжные данные карты;
- пароли;
- паспортные данные;
- секретные ключи;
- лишние личные сведения «на будущее».
